## Pattern-to-fix index

- **WPX-R01 locked built-in code:** offer included functionality freely or remove locked implementation and put paid code in a separate add-on. Do not confuse genuine server-side service processing with license checks.
- **WPX-R02 telemetry:** disable by default; remove or gate all sends behind separate consent, including deactivation/onboarding; document exact payloads and service.
- **WPX-R03 external-service omission:** `== External services ==` in readme with service/purpose/sent data/trigger/terms/privacy; verify working links.
- **WPX-R04 external non-service assets:** bundle locally or use core; check whether exception applies; review compiled source maps.
- **WPX-R05 unsafe privileged flows:** user action + `current_user_can()` for the **specific** operation; nonce/CSRF additionally where needed; ensure public route data is genuinely public.
- **WPX-R06 core/path misuse:** use WordPress hooks and route APIs, `require_once` for required helpers, WordPress path and URL helpers.
- **WPX-R07 data/HTML handling:** validate and sanitize nested data by field, correct REST argument keys, escape late with `esc_*` or `wp_kses` as suitable.
- **WPX-R08 public files:** do not put order/customer PDFs in publicly accessible directories without effective access controls.
- **WPX-R09 packaging and i18n:** remove unnecessary build/temporary files, fix names/case collisions, match translation domain to slug.
- **WPX-R10 runtime/style:** clean WP_DEBUG activation, scoped admin CSS, balanced output buffers and proper `dbDelta` syntax.
- **WPX-R11 truth in advertising:** only promise free features actually implemented; search README, FAQ, screenshots and compiled messages.
- **WPX-R12 arbitrary code insertion:** trace raw CSS/JS/PHP inputs through save/import/render; the new emails request removal in these plugins. Prefer structured controls and programmatically generated output; distinguish generated styles from raw editors and record the reviewer expectation separately from proven exploitation.
- **WPX-R13 global naming collisions:** use distinct plugin prefixes for global functions/constants/options/actions/namespaces; update AJAX registrations and all clients together. A class namespace does not scope an AJAX action string.

## Evidence limitations

- The emails provide examples as identified by WordPress.org; there is no source ZIP for those past reviewed versions included with this skill. Their line numbers are snapshots, not universally valid.
- Some notices are AI-assisted and can be wrong. The skill's reviewer must verify each issue independently.
- Developer reply content was **not** used to infer additional offenses or to assert fixes were actually deployed.
- Email snippets are not API documentation. For example, custom HTML allowlists belong in `wp_kses( $html, $allowed_html )`; `wp_kses_post( $html )` uses the post allowlist. `esc_html()` encodes markup as text rather than preserving rich HTML. Do not copy the emails' malformed KSES example or infer that a `_safe` variable is automatically unsafe.
